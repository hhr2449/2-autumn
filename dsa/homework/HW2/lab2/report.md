## 01.cpp
### 错误类型
Runtime Error 
### 原因
代码中调用了`play(left - 1)`来递归处理连续消除，但是没有考虑`left == 0`的情况，当消除的串恰好在开头的时候,`left-1 = -1`，此时调用`play(left - 1)`会出现越界访问
### 测例构造
```
AAB
1
1 A
```
插入A后序列变为AAAB，调用play将前面三个A消除，此时`left = 0`，调用`play(left - 1)`即为`play(-1)`时,`a.at(-1)`会出现越界访问

## 03.cpp
### 错误类型
Time Limit Exceeded
### 原因
这份代码中使用了一个string来储存珠子序列，并在每次操作时调用 a.insert(a.cbegin() + rank, color) 插入新珠子。每次插入都需要插入字符需要将后续所有字符向后移动，需要O(n)的复杂度。
在最坏情况下，不会发生任何消除，字符串长度持续增长，而每次插入都需移动整个当前字符串。设初始长度为 n，操作次数为 m，则总时间复杂度为O(n*m+m^2),m,n都取到最大值500000，总的操作次数大约为$5\times 10^{11}$,会导致时间超限
### 测例构造
初始序列：使用交替字符 "ABABAB..."，共 500,000 个字符，满足题目“任意三个相邻珠子不同色”的约束，且无连续相同字符。
操作序列：进行 500,000 次插入操作，每次在位置 0 插入字符 'A' 或 'B' 并交替使用。这样始终无两个相邻相同字符，因此不会触发消除逻辑。每次插入都会移动整个序列，根据上面的分析会时间超限
## 04.cpp

### 原因
在移动左边界的时候，使用了`while (left > 0 && a.at(left) == color) --left;`,导致当left减至0时，循环立即终止，且不会检查 a[0] 是否与目标颜色相同。

BA 
1 
1 A

但是在代码执行过程中,left = 1，满足循环条件，将left减至0，此时a[0]为B，与目标颜色不同，但是此时会直接退出循环，未检查a[0]，删除范围就是[0, 3)，导致删除了B，输出错误结果

## 06.cpp
### 错误类型
Wrong Answer
### 原因
代码中使用了分块数组，但是插入操作时未检查当前块是否已满
当某一块的长度达到 4096 后，继续向其中插入字符会执行：
```cpp
memmove(cur + 1, cur, succ_len);
```
其中 succ_len = plen[i] - pos，若 plen[i] == 4096，则写入范围会覆盖到 p[i][4096]。
由于 p 是二维数组 char p[4096][4096]，在内存中连续布局，p[i][4096] 实际等价于 p[i+1][0]，导致下一个块的第一个字符被意外覆盖，造成数据损坏。
### 测例构造
初始字符串：
前 2048 个字符为交替的B和C
后 2 个字符为 "AA"
总长度 = 2050，经 a2p() 后分为两块：
p[0]：2048 字符（"BCBC..."）
p[1]：2 字符（"AA"）
操作序列：
执行2049次在位置0交替插入B和C，使p[0]长度增至 2048 + 2049 = 4097；
第2050次插入A到位置4098。

前面2048次插入会使p[0]被占满，第2049次插入就会使p[1][0]被覆盖掉，第2050次插入A到末尾本来应该可以凑出连续的三个A从而消除，但是由于第一个A被覆盖掉了，无法除法消除操作，随后的输出序列末尾存在2个A

## 07.cpp
### 错误类型
worng answer
### 原因
在确定删除范围的过程中需要移动左边界，左边界的移动可能会跨块，而这里的跨块移动使用了if判断而非while，这就导致了其最多只能跨一个块移动，在前一个块为空时会直接停止移动左边界。实际上前一个块为空应该继续前移，直到左边界无法继续延伸
### 测例构造
测例：1024对AB，填充第一个块，1024对CD填充第二个块，第三个块只有一个B
不断插入C,D来将第二个块删除空，然后将一个B插入第三个块的开头，实际的情况下最后三个元素B可以进行消除，但是在该代码中，左边界在第二个块处就停止了，导致最后的三个B没有进行消除

## 08.cpp
### 错误类型
worng answer
### 原因
该代码在处理珠子消除时，仅执行一轮消除操作，未考虑连锁消除的情况。当插入一个珠子导致某一段 ≥3 个同色珠子相邻而被消除后，左右两侧的珠子会拼接在一起，可能形成新的 ≥3 同色连续段，需继续消除，直到无法再消除为止。然而，该代码在 play 函数中只进行一次局部扫描和消除，没有循环检查消除后是否产生新的可消除段。因此，在存在连消的场景下，程序会提前终止消除过程，导致最终序列中仍残留本应被消除的珠子，从而输出错误结果
### 测例构造
```
AABBAA
1
2 B
```
初始序列为 A A B B A A。
在位置2插入B，即在两个B中间插入一个B，得到：
A A B B B A A
此时中间三个B消除，序列变为：
A A A A
四个A连续，应全部消除，最终为空。
但该代码插入B后检测到BBB，执行一次消除，得到AAAA,退出，未再次检查AAAA 是否可消除，直接结束操作。

## 09.cpp
### 错误类型
Runtime Error
### 原因
这份代码在删除时没有区分同块删除和跨块删除，而是统一执行跨块删除的逻辑。从而导致plen被错误更新。在执行删除逻辑的时候会先执行`plen[l.first] = l.second + 1;`,plen[r.first]被错误更新，变得小于r.second；再执行`int len = plen[r.first] - r.second;`，在这里由于之前的plen[r.first]被错误更新，导致len为负数，后面又执行`plen[r.first] = len;`由于plen是无符号类型，发生溢出，变成一个很大的数，在后面p_to_a()的时候发生数组越界
### 测例构造
```
XXBBYY
1
2 B
```
加入B,序列变为XXBBBYY，则l = 1, r = 5,在删除的时候，plen[0]被更新为2，从而len = 2 - 5 = -3，再执行plen[r.first] = len，plen[0]被赋值为一个负数，由于plen是无符号类型，发生溢出，变成一个很大的数，在p_to_a()的时候发生数组越界

## 10.cpp
### 错误类型
wrong answer
### 原因
```
for (int i = l.first; i < r.first; i++)
    plen[i] = 0;
```
删除操作中的for循环的i少加了一个1，本来的作用是删除中间的块（长度归零），比如左边界在第一块，右边界在第3块，那么第二块直接删除，少加了一个1后会直接将左边界所在的块删掉（长度归0）
### 测例构造
第一块中，前面2046个元素是交替的AB，然后最后两个是FB，第二块中为BF
操作：向第二块的开头插入B，向第二块的开头插入F
第一次插入B会执行删除，此为跨块删除，所以第一块的长度会直接置零。第二次插入F，本来末尾是三个F应该执行删除，但是因为第一块的长度被置为0，所以在延申左边界的时候无法扫描到第一块，从而无法删除，导致F仍然保留在最后的结果中
