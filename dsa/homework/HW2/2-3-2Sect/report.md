## 算法思路和实现要点
1. 该题中的门派可以看作一棵有根树，门人是其中的节点，所以设计一个Node类来表示树的节点，使用一个数组来储存所有的节点，每个节点中储存节点的内力值，以该节点为根的子树内力值之和，使用一个int类型的数组来储存子节点的编号
2. 求解根树的内力值总和：使用递归，以某个节点为根的子树的内力值总和sum即为其子节点的sum总和，根节点的sum为自身的内力值
3. 求解每个节点的引路人：
   * 单调栈：在传承路径中，最靠前的比该节点大节点即为引路人，由此可知：又靠后，内力值又小的节点一定不能成为引路人，这一特点符合单调栈的特点，则可构建一个单调栈类，里面储存节点信息（编号和内力值），一个新的节点进入会淘汰掉单调栈中比该节点小的节点；
   * 递归求解：两个参数：当前求解的节点编号id和id对应的传承路径单调栈stk。从顶部开始遍历单调栈，找到的第一个内力值比节点id大的节点就是引路人；对于id的子节点，找到其中的正统节点（即sum最大的节点），其为正统节点，将id添加到stk中，并由正统节点继承进行递归求解。而其他节点则使用一个新建立的空栈进行递归求解。
   

## 渐进时间复杂度的分析，包含过程
分析主要的两个过程
### 获取每个根树的内力值之和
在这个过程中，每个节点进会被访问一次，时间复杂度为O(n)
### 求解每个节点的引路人
同样从每个节点收到的操作来进行分析：
对于每个节点 i（共n个节点），在整个 find_path 过程中可能经历以下操作：
1. 作为参数被递归调用
次数： 每个节点恰好被调用1次
单次代价： O(1)（不含递归内部的操作，仅考虑调用本身的成本）
总代价： n × O(1) = O(n)
2. 寻找正统弟子时被比较
次数： 每个节点作为某个父节点的子节点被比较1次
单次代价： O(1)
总代价： n × O(1) = O(n)
3. 入栈操作
次数： 每个节点恰好入栈1次
单次代价： O(1)
总代价： n × O(1) = O(n)
4. 作为潜在引路人被检查
这里包含两种情况
   1. 情况4a：被检查后成为引路人
    节点 i 被某个节点 j 检查，发现 val[i] > val[j]
    匹配成功，break 跳出循环
    节点 i 继续留在栈中

   2. 情况4b：被检查后不匹配
    节点 i 被某个节点 j 检查，发现 val[i] ≤ val[j]
    不匹配，继续检查栈中更下面的元素

5. 被弹出栈

* 对于4，5操作，先不考虑4a，先考虑4b，当一个节点被检查后不匹配，在下一个节点入栈的时候一定会出栈，则4,5操作加起来只有两次
* 再将4b考虑进来，虽然同一个节点可以发生多次4a，但是看整个过程，只会有n个引路人产生，所以4b操作的时间复杂度只有O(n)
* 总结起来，整体的时间复杂度T(n) = O(n) + O(n) + O(n) + O(n) + O(n) + O(n) = O(n)


## 渐进空间复杂度的分析，包含过程

1. 单调栈空间：
   显然单调栈中节点数量不会大于n个，每个节点所占据的空间为常数级别，则总共占用的空间复杂度为O(n)
2. 递归栈空间：
   递归的深度即为树高h，最差情况下刚好为一条链,h=n，则递归栈空间为O(n)

总共的总体空间复杂度为O(n)

## 遇到的困难和解决方法

1. 空间复杂度优化：最初想存储完整传承路径会导致O(n²)空间。优化为使用单调栈边遍历边查找，只需要使用O(n)空间
2. 时间复杂度优化：直接在传承路径中查找引路人需O(n)。利用"又老又差"的节点不可能成为引路人的特性，采用单调栈将查找优化到均摊O(1)
