## 算法思路和实现要点
本题其实就是要实现一个循环队列，支持以下操作：
1. 在指定位置插入元素
2. 交换两个位置的元素
3. 整体旋转
4. 区间翻转（包括跨越边界的循环区间）




对于这些操作，如果使用数组或者链表来实现，数组的旋转时间复杂度为o(n),而链表需要遍历链表，时间复杂度为o(n)，显然会超时
于是想到可以使用BBST将操作的时间复杂度降到o(logn)
如果使用标准的BST，则需要考虑选择什么属性作为关键码。如果以节点的序号作为关键码，则很多操作都会使序号改变，这是不行的
于是想到了可以使用treap，它支持：
1. 按排名分裂：天然支持"在第 k 个位置插入"的操作
2. 合并操作：可以高效地将两棵子树合并
3. 而且引入随机的rnd值，可以实现树高渐进O(logn)，这样时间复杂度就可以满足要求了
而且实现简单：代码更简洁，不需要复杂的旋转操作
所以可以使用一个treap来组织节点，中序遍历的结果就是节点之间的顺序。每个节点中储存一个rnd值，rnd值满足堆序性
基本操作：
1. 将树按照中序遍历的区间分裂成两棵树：
   考虑分割点的位置，假设树在序号k处分开。思考中序遍历的特性：对于一个以v为根的树，v在中序遍历中的序号就是$v的左子树size+1$，因此，如果k大于v的序号，则分割点一定在左子树中，则v及右子树一定是分给右分割树；反之，则v和左子树一定是分给左分割树。则可以进行一次拆分，然后向子树中递归解决。
2. 将两棵分割过的树合并：
   u、v分别为左、右分割树，根据rnd的堆序性（假设是小根堆），则u,v的rnd值一定是他们子树中最小的。则对于合并后的树，rnd值一定为u,v的rnd值中的最小值，也就是rnd小的节点作为根节点。以u作为根节点为例，则u左子树是已经确定的，v存在于u的右子树中，则将v和u的右子树递归合并，再接到u上面即可。
3. 懒操作翻转：假设要将一个子树的中序序列翻转，只需要对每个节点交换两个孩子即可。但是对于子树的遍历是很花时间的，所以可以
   引入懒标记：每个节点设置isRev来记录是否要翻转，然后将要反转的树的根节点取反（因为翻转两次相当于不反转），结束操作。等到后序其他操作（合并，分割，输出）等操作遇到有标记的节点时，将节点的孩子翻转，然后将懒标记下推到两个孩子即可。


题目中的四种操作：
1. 在指定位置插入元素：
   进行分割，以指定位置P为界拆分成两棵树，将新增节点和左子树合并，再将两棵树合并，这样得到的树的中序遍历序列中新增节点恰好就是位于p
2. 交换两个位置的元素：
   进行搜索：搜索过程可以通过类似于拆分的思路进行，只需要根据左子树的大小决定向左还是向右即可。
   搜索到两个节点之后，直接让他们交换代号即可
3. 整体旋转：整体旋转r位相当于将序列`[0, cnt) = [0, cnt - r) + [cnt - r, cnt)变成[cnt - r, cnt) + [0, cnt - r)`。只需要整棵树以cnt-r为界进行拆分，然后交换位置进行合并即可。
4. 区间翻转：
   区间翻转就是对区间对应的根树进行翻转，通过两次拆分找到根节点并且打上懒标记即可
   如果是一整个区间，则直接打标记
   如果是两个分开的区间，可以先将两个区间进行合并，再翻转，最后进行合并即可

## 渐进时间复杂度的分析，包含过程

当rnd随机取值的时候，treap的树高是渐进O(logn)的
单次操作分析：
1. split
   $O(log⁡n)$：沿树高递归，每次必定下降一层，每层常数操作
2. merge
   $O(log⁡n)$：沿树高递归，每次必定下降一层，每层常数操作
3. find_kth
   $O(log⁡n)$：沿树高递归，每次必定下降一层，每层常数操作
4. insert
   创建新节点，花费$O(1)$时间，之后会调用一次split和两次merge，时间复杂度$O(logn)$
5. swap
   进行两次find_kth，时间复杂度$O(logn)$
6. rotate
   进行一次split和merge，时间复杂度$O(logn)$
7. reverse
   最坏情况是循环区间的情况，需要调用两次split分开，调用一次merge合并出完整区间进行翻转，调用一次split分割，再进行两次merge合并，总共三次split和merge，时间复杂度$O(logn)$

总共有M次操作，每次操作的时间复杂度为$O(logn)$；再加上最后输出N个值，所以时间复杂度是$O(MlogN + N)$

## 渐进空间复杂度的分析，包含过程

主要消耗空间是节点的储存和递归栈
总共N个节点，每个节点占用$O(1)$空间，需要$O(N)$空间
递归栈的最大深度不超过树高，所以栈空间为$O(logN)$
总共消耗空间为$O(N)$

## 遇到的困难和解决方法

1. 最初尝试用 offset 模拟旋转
   最初设计了一个 offset 变量来记录旋转偏移量，试图将"树中位置"和"真实位置"分离，避免旋转时实际操作树。
   但是忽略了插入操作会使部分元素的位置发生改变，所以没有办法使用全局的offset进行映射
   解决方法：放弃 offset 方法，直接在树上执行旋转操作（通过 split 和 merge 交换两部分的顺序）。

2. push_down操作
   在split和merge之前应该先进行翻转标记的检查，否则可能会出现左右子树的错位
